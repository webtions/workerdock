# Architecture

SwiftUI + AppKit, macOS 14+. One central observable model, a handful of small service types, and views that
read the model. No third-party UI frameworks. Project file is generated by XcodeGen (`project.yml`).

## Folder layout (`WorkerDock/`)
| Folder | Contents |
|---|---|
| `App/` | `WorkerDockApp.swift`: scenes (main window, About window, menu bar extra, Settings), the app delegate (launch, login-item launch handling, quit confirmation, debug hooks) |
| `Core/` | `AppModel.swift` (central state and actions), `Persistence.swift`, `ShellEnvironment.swift`, `AppCatalog.swift` (terminal/editor detection), `AppUpdater.swift` (Sparkle), `DemoData.swift` |
| `Discovery/` | `ProjectScanner` (find configs), `ConfigParser` (TOML/JSON/JSONC to bindings), `ProjectInspector` (framework, CMS, package manager, Wrangler version, run mode), `RootWatcher` (FSEvents) |
| `Process/` | `ProcessManager` (spawn/stop), `OutputParser` (read URL, port conflicts from output), `PortAllocator`, `ProcessInspector` (libproc: memory, start time, cwd), `RunningDetector` (find terminal-started servers) |
| `Models/` | `Models.swift`: `Project`, `ProjectInfo`, `WorkerBinding`, `RunModeKind`, `PackageManager`, `ProjectRuntime`, `LogBuffer`, `AppSettings`, `AppInfo`, status types |
| `Views/` | All SwiftUI views and the design tokens (`Theme.swift`) |
| `Resources/` | `Assets.xcassets` (app icon), `Icons.xcassets` (Lucide icons, brand marks) |

Tests are in `WorkerDockTests/` (28 tests: parsing, process management, discovery, port detection).

## Central model: `AppModel`
`@Observable`, `@MainActor`, singleton `AppModel.shared`. Holds:
- `projects`, `roots`, `settings` (persisted), `infos` (parsed per project, in memory), per-project
  `ProjectRuntime` (status, url, pid, memory, log buffer, port conflict, external-process info).
- Actions: scan, start/stop/restart, start on a free port, favourite/hide/remove, open in
  browser/editor/terminal, memory sampling, orphan recovery, quit handling.
- Views read it through `@Environment(AppModel.self)`.

## Key flows
**Discovery.** `ProjectScanner` walks the root folders (skip list) and finds wrangler configs. `RootWatcher`
(FSEvents, optional) triggers rescans. `ProjectInspector` then reads each project: parses the config
(`ConfigParser`, TOMLKit for TOML, a JSONC stripper for JSON), finds the nearest `package.json`, lockfile
(package manager), installed Wrangler/Vite plugin versions, framework/CMS markers, and decides the run mode.

**Starting a project.** `AppModel.startAsync` checks dependencies are installed (otherwise shows the install
command, never installs), allocates a port and inspector port (`PortAllocator`, from 8787 / 9230), builds the
command for the run mode, and asks `ProcessManager` to spawn it with `posix_spawn` in its own process group,
using the login-shell environment (`ShellEnvironment`). Output lines go to `handleLine`, which appends to the
ring buffer (5,000 lines, ANSI stripped), detects "Ready on http://..." (marks Running and records the URL),
detects an already-running server (adopts it) and detects "address already in use" (sets `portConflict`).

**Stopping.** SIGTERM to the whole process group, SIGKILL after 5 seconds. Quit asks first if projects are
running and stops them all.

**Terminal-started servers.** `RunningDetector` scans `workerd` processes (libproc, no `lsof`) and matches
them to projects by working directory. They show as Running with `external = true`: they can be stopped
(with confirmation) or restarted under WorkerDock (which then captures logs).

**Crash recovery.** Running PIDs are recorded in `running.json` with their start time. On launch, leftovers
from a crash are found (guarded against PID reuse) and the user is asked whether to stop them.

**Memory.** `ProjectDetailView` samples every 3 seconds while a project is on screen and running: resident
size of the whole process group (or of the external PIDs), shown as a coloured badge (green < 400 MB, amber
< 800 MB, red above).

**Port conflicts.** `OutputParser.detectPortInUse` reads the port from the error text. The owner is another
running project on the same port if we know one. The Overview shows a banner with "Start on a free port",
which restarts with `--port N` passed through (`PackageManager.runDev(port:)`).

**Updates.** `AppUpdater` wraps Sparkle's `SPUStandardUpdaterController`. Disabled in debug builds and tests
unless `WORKERDOCK_UPDATER=1`.

## UI structure
- `MainView`: `NavigationSplitView`. Sidebar (search, Favorites / Running / Stopped, footer with Add and
  Settings) and detail.
- `ProjectDetailView`: header (logo, name, status and memory chips, path, type chips, site/admin links,
  Restart/Stop/Start, more menu) and a tab bar: Overview, Logs, Explorer, Settings.
- `OverviewView`: banners (dependencies, port conflict, parse errors), `BindingsSection` (diagram or list),
  Details table (every value has a copy button).
- `LogsView` + `LogTextView`: filter, follow, copy, clear; the log is one `NSTextView` so text can be
  selected across lines.
- `ExplorerView`: `WKWebView` that exists only while the tab is visible and the project runs.
- `ProjectSettingsView`: run mode, custom command, port.
- `SettingsView` (⌘,): theme, open at login, Dock icon, updates, project folders, access status, terminal and
  editor choice, Node path, shell environment.
- `MenuBarContent`: the menu bar menu. `AboutView`: About window.

## Where data lives (nothing in project folders)
`~/Library/Application Support/WorkerDock/`
- `registry.json`: root folders and projects (including hidden, favourite, port, run-mode override, custom command).
  Optional fields are optional so older files keep loading.
- `settings.json`: appearance, Dock icon, terminal/editor, Node path, watch roots.
- `running.json`: PIDs started by the app (for crash recovery).

Other state: UI preferences in `UserDefaults` (domain `dev.workerdock.app`, e.g. bindings layout, window
frame).

## Environment variables (debug and tests)
| Variable | Effect |
|---|---|
| `WORKERDOCK_DEMO=1` | Use invented demo projects; persists nothing (for screenshots) |
| `WORKERDOCK_DEMO_TAB=logs` | Open a given tab in demo mode (overview, logs, explorer, settings) |
| `WORKERDOCK_WIDTH=820` | Resize the window shortly after launch |
| `WORKERDOCK_UPDATER=1` | Enable Sparkle in a debug build |
| `WORKERDOCK_SUPPORT_DIR` | Override the Application Support folder (tests) |
| `WORKERDOCK_DEBUG_*` | Headless debug hooks (start a project, add a root, render the icon, snapshot tabs) |
